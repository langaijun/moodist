# Moodist 需求文档

## 1. 项目概述

### 1.1 项目背景
Moodist 是一个免费开源的环境音效生成器，旨在为用户提供专注、放松和创造力激发的声音环境。在现代社会中，人们经常面临注意力分散、压力过大等问题，合适的环境音效可以帮助用户进入更好的专注状态，提升工作和学习效率。

### 1.2 项目目标
- 提供高质量、多样化的环境音效
- 支持多音效同时播放和个性化调节
- 简洁直观的用户界面
- 跨平台可用（Web + PWA）
- 完全免费和开源

### 1.3 目标用户
- 远程工作者：需要专注环境提升工作效率
- 学生群体：学习时需要背景音乐或白噪音
- 冥想爱好者：需要环境音效辅助放松
- 睡眠障碍者：需要白噪音助眠
- 创作者：需要特定氛围激发灵感

## 2. 功能需求

### 2.1 核心功能需求

#### 2.1.1 音效播放
**需求描述**：用户能够播放、暂停、停止各种环境音效。

**具体要求**：
- 支持单个音效的独立播放控制
- 支持多音效同时播放（混音功能）
- 播放状态实时显示
- 播放/暂停全局控制
- 音效循环播放支持

**优先级**：P0（最高优先级）

---

#### 2.1.2 音量控制
**需求描述**：用户能够精确控制每个音效的音量以及全局音量。

**具体要求**：
- 每个音效独立的音量滑块控制
- 全局音量控制（同时影响所有音效）
- 音量范围：0-100，默认值50
- 音量变化实时生效
- 音量状态持久化保存

**优先级**：P0

---

#### 2.1.3 音效分类
**需求描述**：将音效按类别组织，方便用户查找和选择。

**具体要求**：
- 至少包含以下分类：自然、雨声、动物、城市、场所、交通、物品、噪音
- 每个分类有明确的图标和名称
- 分类内音效按逻辑顺序排列
- 支持分类展开/收起（如果音效数量较多）

**优先级**：P0

---

#### 2.1.4 音效选择
**需求描述**：用户能够方便地选择和取消选择音效。

**具体要求**：
- 点击音效卡片即可选择/取消
- 选中的音效有明显视觉区分
- 支持键盘操作（Enter/Space键）
- 支持一键取消所有选择

**优先级**：P0

---

#### 2.1.5 收藏功能
**需求描述**：用户能够收藏常用的音效组合。

**具体要求**：
- 每个音效都有收藏按钮
- 收藏的音效显示在"收藏"分类中
- 收藏状态持久化保存
- 收藏数量无限制

**优先级**：P1

---

#### 2.1.6 预设管理
**需求描述**：用户能够保存和管理音效预设配置。

**具体要求**：
- 创建新的预设（包含当前所有选中音效和音量设置）
- 为预设命名
- 删除预设
- 快速应用预设
- 预设数据本地存储

**优先级**：P1

---

#### 2.1.7 音效分享
**需求描述**：用户能够分享当前音效配置给其他人。

**具体要求**：
- 生成包含当前音效配置的URL
- 一键复制分享链接
- 链接格式：`https://moodist.app/?share={配置数据}`
- 支持通过URL恢复音效配置

**优先级**：P1

---

### 2.2 扩展功能需求

#### 2.2.1 实用工具集
**需求描述**：集成提高用户生产力的小工具。

**具体工具**：
- **番茄钟**：25分钟工作 + 5分钟休息的计时器
- **倒计时**：自定义时长的倒计时器
- **记事本**：简单的文本编辑器
- **待办事项**：任务清单管理
- **呼吸练习**：引导式呼吸训练
- **双耳节拍**：脑波频率调节音效
- **等时节拍**：等时音调播放

**优先级**：P2

---

#### 2.2.2 睡眠定时器
**需求描述**：设置定时器在指定时间后停止播放。

**具体要求**：
- 支持5分钟到2小时的自定义时间
- 时间到后淡出停止（避免突然停止的突兀感）
- 定时器运行中显示剩余时间
- 支持取消定时器

**优先级**：P2

---

#### 2.2.3 键盘快捷键
**需求描述**：支持常用操作的键盘快捷键。

**快捷键列表**：
- `Shift + Space`：播放/暂停
- `Shift + R`：取消所有选择
- `Shift + H`：显示快捷键帮助
- `Shift + S`：分享当前配置
- `Shift + Alt + P`：打开预设管理
- `Shift + Alt + T`：打开睡眠定时器
- `Shift + B`：打开呼吸练习
- `Shift + P`：打开番茄钟
- `Shift + N`：打开记事本
- `Shift + T`：打开待办事项
- `Shift + C`：打开倒计时

**优先级**：P2

---

### 2.3 技术需求

#### 2.3.1 响应式设计
**需求描述**：应用在不同设备和屏幕尺寸上都能良好显示。

**具体要求**：
- 支持桌面端、平板、手机
- 最小支持宽度：320px
- 触摸设备优化手势操作
- 移动端优化的UI布局

**优先级**：P0

---

#### 2.3.2 离线支持
**需求描述**：支持PWA功能，可离线使用。

**具体要求**：
- 支持安装为桌面应用
- 离线时仍可播放已缓存的音效
- 离线时保存用户设置
- 提供离线提示

**优先级**：P1

---

#### 2.3.3 性能要求
**需求描述**：确保良好的用户体验和性能表现。

**具体指标**：
- 首屏加载时间 < 2秒
- 音效加载延迟 < 1秒
- 内存占用 < 100MB
- 支持同时播放8个以上音效
- 页面操作响应时间 < 100ms

**优先级**：P0

---

#### 2.3.4 兼容性要求
**需求描述**：支持主流浏览器和设备。

**支持平台**：
- Chrome/Edge 90+
- Firefox 88+
- Safari 14+
- 移动浏览器（iOS Safari, Chrome Mobile）
- 桌面和移动设备

**优先级**：P0

---

### 2.4 用户体验需求

#### 2.4.1 视觉设计
**需求描述**：采用东方美学配色，营造平静专注的氛围。

**设计要求**：
- 主色调：古绢原色背景 (#F2EADA)
- 强调色：青葡萄色 (#A8E4A0)
- 辅助色：石青 (#224B5E)
- 文字色：松烟墨 (#2C2C2C)
- 副文字色：矿物赭石 (#8B4513)
- 整体风格简洁、温暖、专业

**优先级**：P0

---

#### 2.4.2 交互体验
**需求描述**：提供流畅直观的交互体验。

**具体要求**：
- 所有动画过渡时间 < 300ms
- 操作反馈及时明确
- 避免不必要的弹窗和打断
- 支持撤销/重做关键操作
- 提供操作引导和帮助

**优先级**：P1

---

#### 2.4.3 无障碍支持
**需求描述**：支持残障用户使用。

**具体要求**：
- 完整的键盘导航支持
- ARIA标签和角色定义
- 屏幕阅读器友好
- 足够的颜色对比度
- 支持焦点管理

**优先级**：P1

---

## 3. 非功能需求

### 3.1 安全性
- 不收集用户个人数据
- 不追踪用户行为
- 开源代码，安全透明
- 使用HTTPS加密传输

### 3.2 可维护性
- 代码结构清晰，模块化设计
- 完整的类型定义（TypeScript）
- 详细的代码注释
- 统一的代码风格

### 3.3 可扩展性
- 模块化架构，易于添加新功能
- 支持插件式扩展
- 数据结构支持动态更新

### 3.4 可测试性
- 组件化设计，易于单元测试
- 提供测试用例
- 支持自动化测试

## 4. 数据需求

### 4.1 本地存储
- 用户设置：localStorage
- 音效状态：localStorage
- 预设配置：localStorage
- 工具数据：localStorage

### 4.2 音效资源
- 格式：MP3
- 质量：高质量（至少128kbps）
- 大小：每个文件 < 5MB
- 总数量：至少50个音效

### 4.3 数据结构
```typescript
// 音效数据结构
interface Sound {
  id: string;
  label: string;
  icon: React.ReactNode;
  src: string;
}

// 用户状态结构
interface UserState {
  sounds: Record<string, {
    isSelected: boolean;
    isFavorite: boolean;
    volume: number;
  }>;
  globalVolume: number;
  isPlaying: boolean;
}

// 预设结构
interface Preset {
  id: string;
  label: string;
  sounds: Record<string, number>;
}
```

## 5. 约束条件

### 5.1 技术约束
- 必须使用现代前端框架（React + Astro）
- 音效播放使用Howler.js库
- 状态管理使用Zustand
- 支持TypeScript

### 5.2 资源约束
- 音效文件需要CDN加速
- 图片资源优化压缩
- 总包体积 < 5MB

### 5.3 时间约束
- 首个版本开发周期：2-3个月
- 后续迭代：每月一次功能更新
